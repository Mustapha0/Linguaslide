# LinguaSlides Studio

A React/Vite presentation-building prototype for linguistics and English studies, with a browser-side editable PowerPoint (`.pptx`) export path powered by PptxGenJS.

## Get the Android APK from GitHub

1. Create a new GitHub repository.
2. Upload the **contents** of this ZIP to the repository root (so `package.json` and `.github` are at the top level, not inside a folder).
3. Open **Actions**, enable workflows if prompted, and run **Android APK Build** (it also runs on every push to `main`).
4. When it finishes, download the `linguaslides-debug-apk` artifact. It contains `app-debug.apk`; copy it to your phone and install it.

The Android project is generated in the workflow with Capacitor, so no `android/` folder is stored in the repo. In the Android app, **Download JSON** and **Export editable PowerPoint** are saved directly to **Documents/LinguaSlides** on Android 10+ (older Android versions open the Save-as picker). Android requires you to confirm the destination; the app cannot silently write to arbitrary public folders.

### App icon
The Android launcher icons are generated by the workflow (step "Apply app icon"), which embeds the icon image directly in `.github/workflows/android.yml`. No extra icon files are needed in the repo. The web favicon is `public/favicon.png`.

## Quick start

Requirements: Node.js 18+ and npm. Internet access is required the first time you install dependencies.

```bash
npm install
npm run dev
```

Open the localhost URL printed by Vite. To build a production bundle:

```bash
npm run build
npm run preview
```

## Workflow

1. Search and filter the 20 visual-system concepts.
2. Select a theme and inspect the slide map / preview.
3. Choose a title and presentation language, then create the deck.
4. Inspect or download the structured JSON deck object.
5. Select **Export editable PowerPoint (.pptx)** to generate a PowerPoint file locally in the browser.

The generated `.pptx` contains editable PowerPoint text boxes and vector shapes rather than a single screenshot per slide. The exporter includes layouts for IPA charts, minimal pairs, interlinear gloss examples, syntax trees, schematic dialect maps, and corpus/concordance-like excerpts. Each slide gets speaker notes. Slide content is intentionally a starter scaffold; edit the generated deck in PowerPoint to replace illustrative examples with your research data.

## Project structure

- `src/LinguaSlidesGallery.jsx` — theme gallery, build flow, JSON inspector, preview and export controls.
- `src/LinguaSlides.css` — responsive styling.
- `src/pptxExport.js` — PptxGenJS renderer.
- `tests/pptx-export.test.js` — integration tests for package integrity, slide XML and speaker-note parts.
- `scripts/validate-pptx.sh` — test/build validation entry point.
- `examples/linguaslides-phonetic-waveform-sample.pptx` — sample editable PowerPoint deck created and opened through LibreOffice PDF conversion.
- `reference-overview.png`, `reference-dashboard.png` — supplied visual references.

## Validate the exporter

After installing dependencies, run:

```bash
npm test
npm run build
```

The integration test generates a temporary PPTX, checks its ZIP package integrity, confirms slide XML and speaker notes exist, and then removes the test file. `scripts/validate-pptx.sh` runs both the test suite and production build.

## Compatibility and known limitations

- The exporter creates real `.pptx` files, but a successful build/test on your machine is still the final compatibility check. The sample `.pptx` included in `examples/` was generated with editable text/vector objects and successfully opened/converted to PDF by LibreOffice. The React app dependency installation/build and its browser-side PptxGenJS integration tests could not be completed in the packaging environment, so those checks still need to be run after `npm install`.
- IPA glyph appearance depends on the fonts installed on the machine opening the file. Fonts are not embedded. For publication or teaching, verify IPA coverage (for example with a SIL IPA font) on the target computer.
- Some charts, waveforms, maps and diagrams are illustrative editable shapes, not imported experimental data or geographic boundaries. Replace them with validated source data before presenting research results.
- The theme's advertised slide count is respected by deck creation; if a theme outline is shorter, supplementary scaffold slides are added.
- This is a client-side prototype, not a multi-user cloud service. It has no account system, server persistence, billing, or collaborative editing.
- Layouts are representative and editable, but the PowerPoint output is not pixel-identical to every HTML theme preview. Some fonts may substitute across operating systems.

## Troubleshooting

- If `npm install` fails, use Node.js 18+ and retry on a network that can reach the npm registry.
- If export reports an error, open the browser developer console and copy the message; the UI also displays the error.
- If IPA characters appear as empty boxes, install a Unicode IPA font on the computer opening the deck, then reopen the presentation.

## Slide preview and saving to Documents

After selecting a theme and pressing **Create Deck**, use **Preview your deck** to select slides and edit each slide's title, body text, and speaker notes. You can move slides up/down, duplicate them, and delete them (at least one slide is kept). Edits are included in the PPTX and JSON exports.

On browsers that support the File System Access API (typically desktop Chromium browsers), the export button opens a native Save dialog. Choose your device's **Documents** folder there to save the `.pptx` or `.json` directly to that folder. Browsers do not allow a website to silently write into Documents without user consent. On browsers without that API, LinguaSlides downloads the file using the browser's normal download location; configure your browser's download location as Documents if desired.

## Import and export templates as JSON

The template gallery includes **Import Template from JSON** and **Export Selected Template JSON**. Import a `.json` file from Android storage (or the browser file picker). Imported templates are validated and stored locally in this app's browser storage, so they remain available on that installation after restart. Exported templates can be reused or shared.

Minimum import format:

```json
{
  "id": "my-template",
  "name": "My Linguistics Template",
  "description": "A reusable academic slide design",
  "category": "Linguistics",
  "tags": ["Linguistics", "Research"],
  "layout": "map",
  "theme": {
    "background": "#F3F0E5",
    "primary": "#293B36",
    "text": "#293B36",
    "muted": "#68766E",
    "accent": "#B35E45",
    "fontFamily": "Source Serif 4"
  },
  "layouts": [
    { "type": "title", "title": "Research title", "body": [] },
    { "type": "content", "title": "Research question", "body": ["Add content here"] }
  ]
}
```

`name` and a non-empty `layouts` (or `slides`) array are required. Colors must be six-digit hex values (for example `#B35E45`). Supported layout values are `frame`, `map`, `wave`, `grid`, `split`, `code`, `tree`, and `band`; if omitted, the importer infers a layout from the template id/name. Theme colors may be provided as `theme.background`, `theme.primary`/`theme.text`, `theme.muted`, and `theme.accent`, or through `theme.colorTokens.background/primary/secondary/accent`. A wrapped `{ "template": { ... } }` object and deck-style `theme.typeface` are also accepted. Invalid explicit colors and unsupported explicit layouts produce validation errors instead of silently falling back. See `examples/map-isogloss-custom-template.json` and run `npm test` for importer regression tests. The importer creates a gallery theme from the JSON; it does not execute arbitrary JSON or treat imported data as code.


## Export integrity fix

The Android document saver uses `FileInputStream` for API compatibility, stages non-empty export bytes in app-private cache, writes through Android's document provider with an explicit byte count, flushes/closes streams, and verifies the saved document by reading it back. Export failures are surfaced instead of reported as success. This source change still requires a successful GitHub Actions build and on-device test.

## Build an Android APK on GitHub

1. Create an empty GitHub repository and upload the contents of this project ZIP to the repository root (not the ZIP itself).
2. Commit the files to the `main` branch (or `master`).
3. Open **Actions → Android APK Build** and wait for the workflow to finish.
4. Open the completed workflow run and download the `linguaslides-debug-apk` artifact. Extract the artifact ZIP to get `app-debug.apk`.
5. Transfer the APK to your Android device and install it. Android may ask you to allow installation from the app used to open the APK.

The workflow builds a debug APK for testing; it is not a Play Store release-signed APK. GitHub Actions is the build environment, so an APK is not included in this source ZIP. Confirm the workflow succeeds and test import/export on your own device before relying on it.

## Plain white template example

`examples/plain-content-template.json` is a minimal template-gallery import example for this
project's importer. It uses the supported `frame` layout, a white background, dark text, and
a `layouts` array. Import it from **Import Template from JSON**.

This is a reusable template definition, not a deck file. The gallery importer maps layout
headings into a gallery theme; it does not render arbitrary `slots.body` deck fields. Use the
app's slide editor to enter slide text after importing the template.
